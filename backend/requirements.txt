# Every direct dependency is pinned to an exact version.
#
# It was not, and on 2026-07-29 that took production down: `mcp>=1.28.0` had no ceiling,
# MCP 2.0 moved a module we import, and the next rebuild — whenever it came, whatever else
# was in it — failed to start. The rebuild that triggered it was an unrelated DNS fix,
# which is the point: an open upper bound means the failure lands on whoever deploys next
# rather than on whoever chose the version.
#
# Reviewing the rest showed the same shape everywhere and how far it had already carried
# us: croniter was declared >=2.0 and running 6.2, gunicorn >=21.2 running 26.0. Those
# jumps happened silently across past rebuilds and happened not to break. That was luck.
#
# The versions below are the ones production is proven to be running right now. The trade
# is deliberate: security updates no longer arrive on their own, so they are bumped on
# purpose, tested, and deployed — rather than arriving unannounced in an unrelated deploy.
#
# Transitive dependencies are still unpinned. A full lockfile would close that too and is
# worth doing; this closes the part that actually bit us.
