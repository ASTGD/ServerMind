## 3. The hero — the OpenReplay pattern (PM: *"I must want this type of hero"*)

I inspected `openreplay.com` directly. The pattern is **not** a centered text hero. It is:

```
┌──────────────────────────────────────────────────────────────┐
│  DARK NAVY, edge-to-edge                                     │
│                                                               │
│  ┌── 45% ─────────────┐   ┌── 55% ──────────────────────┐   │
│  │                    │   │   ╭─ soft curved glow ─╮     │   │
│  │  HUGE HEADLINE     │   │  ┌──────────┐                │   │
│  │  tight leading     │   │  │ UI panel │ ┌───────────┐  │   │
│  │  3 lines, w-800    │   │  └──────────┘ │ UI panel  │──┼──▶ bleeds
│  │                    │   │      ┌────────┴───────┐   │  │   │  off-canvas
│  │  muted sub, 2 ln   │   │      │   UI panel     │───┼──┼──▶
│  │                    │   │      └────────────────┘      │   │
│  │  [Filled] [Ghost]  │   │   layered · overlapping ·    │   │
│  │                    │   │   different depths           │   │
│  │  ── proof strip ── │   └──────────────────────────────┘   │
│  └────────────────────┘                                       │
└──────────────────────────────────────────────────────────────┘
```

**The distinctive ingredients — reproduce all five:**

1. **Asymmetric split**, not centered. Text left ~45%, visual right ~55%.
2. **Deep navy ground** (`#0B1020`–`#12123A` family) — the whole hero is dark, edge to edge.
3. **A layered COLLAGE of light UI panels** on the right — *never one flat screenshot*.
   Multiple cards at different z-depths, overlapping, subtly rotated, each with its own
   border + soft shadow. Light cards on dark ground = the contrast that carries the hero.
4. **Panels crop off the right edge**, implying more beyond the fold.
5. **A large soft curved glow** behind the panels — an organic arc/sweep that lifts them
   off the background. This is what makes it feel designed rather than assembled.

**Left column:** headline at ~64–76px desktop, weight 800, leading ~0.95, `text-wrap:
balance`. Muted sub (~16px, 2 lines). Two CTAs: **filled** `Start free` + **ghost**
`See how it works`, each with a small icon.

**⚠️ The one part we must NOT copy:** OpenReplay closes the hero with *"Trusted by Uber,
Amazon, Mercedes…"*. **We have no customers.** Replace that slot with the **real evidence
strip** (§5) — honest, and frankly more interesting than borrowed logos.

## 8. How It Works — the interactive centrepiece (v2)

Use the **real scenes** in `how-ally-works-scenes.md` — Scene 1 ("my website got hacked")
is the hero scene. They are real things Ally did, not mock-ups.

**The one idea to land, on every scene:** *Ally never does anything destructive on its own.*

**v2 = more premium than last time.** Suggested lift:
- A **scroll-driven narrative** — the story advances as you scroll, one scene per beat.
- **Typed chat** that reveals message-by-message, with the mission card assembling beside
  it — step ticks landing in sequence, the ✓ Verified chip last.
- A **sticky scene rail** (left) tracking progress through the story.
- **One real interactive moment**: let the visitor *click Approve* on a risky step and
  watch the mission continue. That single interaction communicates the whole safety model
  better than any paragraph.
- Respect `prefers-reduced-motion`: reveal instantly instead of animating.

## 9. Craft bar

- **Not the AI-generated look.** Avoid: cream `#F4F1EA` + serif + terracotta; a lone acid
  accent on near-black; purple→blue gradient hero on white; Inter/Space Grotesk as the
  "safe" pick; emoji as section markers; everything centered; `rounded-lg` on everything.
  We already have a real palette (§4) — spend the boldness on the hero glow and the
  typography, keep everything else quiet.
- **Layout does the spacing** — flex/grid + `gap`, not per-element margins.
- Wide content scrolls in its own `overflow-x:auto`; the body never scrolls sideways.
- Visible focus states; real `<button>`/`<a>`; keyboard reachable.
- ~65ch measure on body copy; `text-wrap: balance` on headings.
- Watch selector specificity — that's where the spacing quietly breaks.
- Generative/decorative graphics: **Canvas or WebGL**, not hand-authored SVG path soup.

## 9b. Output location & tech

**Build into `marketing-site/`** at the repo root (create it). Do not touch `frontend/`
(that is the product app) or any `backend/` file.

```
marketing-site/
├── index.html            ← Home
├── how-it-works.html     ← the interactive centrepiece
├── pricing.html
├── security.html
├── proof.html
├── assets/
│   ├── css/  js/  fonts/ (inlined data-URI sources)
│   ├── logo/             ← copy from ../marketing-brief/assets/logo/
│   └── media/            ← the ONE gif (§6)
└── README.md             ← how to preview + deploy notes
```

**Tech: plain static HTML + CSS + vanilla JS.** No build step, no framework, no CDN.
Reasons: it deploys to `serverally.firevps.net` as static files behind OpenLiteSpeed with
zero infrastructure, it caches perfectly, it cannot break the product app, and it has no
dependency that can rot. Animation via CSS + the Web Animations API; use Canvas/WebGL only
for genuinely generative visuals. Share one stylesheet + one JS bundle across the pages.

**No external requests at all** — fonts inlined as data-URIs, all graphics generated
inline. A linked font/CDN will silently fall back and the design will quietly degrade.
